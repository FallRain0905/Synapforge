## 选择卡协议（三个角色共用，非工作流资产）

`mm-analysis` / `mm-modeling` / `mm-topic` 的"需要用户拍板"段落里新增的一句**来自平台交互协议**，不是数学建模工作流的底料：
对话通道的内核在**每一轮**的提示词末尾注入 `synapforge-choice` 协议说明（`apps/agent/chat_loop.py` 的
`CHOICE_PROTOCOL_INSTRUCTION`），页面把回复末尾的这个 fenced block 渲染成可选择、可提交的表单。
角色里补这一句的理由：这三个角色的输出契约天生以"把选择权交回用户"结尾，若不点明机制，模型容易写成
"回复 1/2/3"这种对话里无法回传的自由文本。**判据也写进了角色**：只有"在现成选项里二选一/多选"才出卡片，
缺材料/要复核的待确认项仍走文字清单——避免每轮都塞一张卡片。

## 变更纪律

1. 改角色提示词 → 改本目录的 md → 跑 `python scripts/prompt_lint.py` → 重跑部署脚本第 6 步（引擎会覆盖执行体上的副本）。
2. 提示词里**不得出现**仓库内路径（`_utils/`、`scripts/`、`figures/`、`user_data/`、`CLAUDE.md`）——
   对话通道没有这些文件，写进去等于诱导角色去调用不存在的东西（lint 会拦）。
3. frontmatter **不写 `model`**：模型由页面的模型下拉决定，两处都写会打架（lint 会拦）。
4. 工具的开关是**真的**（实测 `tools: {bash: false}` 生效）：只读角色不该给它写权限——"独立性"正是靠这条落地的。
5. **`description` 的格式是约定**：`短名 · 一句话`——页面的角色下拉**取「·」前的部分当标签**（放不下长句），
   整句作为悬停说明与选项提示。所以「·」前必须是**短名（≤ 8 字）**，别把整句话写在那里
   （实测踩到：写成「数学建模与统计建模中文论文写作」会把工具条撑得很长；写成「文献检索与证据整理：…」
   没有「·」时下拉会退回显示英文 id `mm-research`）。
