# 桌面端「完整功能客户端」计划（DESKTOP-GUI）

> 2026-09-23 · 状态：**已实施并上线**（用户选路线 A；D-1/D-2 全部交付，D-3 未做）
> 交接：`docs/handoffs/DESKTOP_GUI_EMBEDDED_WORKBENCH_HANDOFF.md`
> 上游：`docs/DESKTOP_CLIENT_PLAN.md`（选型）、`docs/DESKTOP_CLIENT_IMPLEMENTATION_PLAN.md`（DP 阶段）
> 本文回答用户 2026-09-23 的问题：**能否彻底封装成桌面端 GUI、一个完整功能的桌面客户端？**

## 0 结论先说

**能，而且不用重写界面。** 现有桌面端是一个 720×560 的"内核状态页 + 托盘"，
平台工作台靠 `shell.openExternal()` 丢给系统浏览器打开（`apps/desktop/src/main.js:161`）。
把它变成"完整功能客户端"的正确做法不是**重画 UI**，而是**把已有的 25 页工作台搬进应用窗口**，
再补上只有桌面端才有的能力（通知、自启、角标、拖拽上传、深链）。

代价集中在三处（都不大，但要提前认）：**安装包会变重**（Electron ≈ 100MB + 内核 ≈ 40MB + 前端产物几 MB）、
**未签名**（用户首次安装会看到 SmartScreen 提示，并需要"更多信息 → 仍要运行"）、
**前端升级与客户端升级解耦不清**（取决于 §3 选哪条路线）。

## 2 「完整」的定义（可验收清单）

一个"完整功能的桌面客户端"= **不打开浏览器就能完成全部日常操作**：

1. 登录 / 注册 / 退出（含会话保持）
2. 项目工作区：聊天流（含 `/task`、附件、@提及）、任务板、成果空间、概览
3. 任务与流程、我的任务、成果物、文档版本、审核门禁、交接中心
4. 团队与成员、设备与接入（本机配对、项目授权）
5. **本机内核面板**（现在的状态页）并入主窗口，而不是另一个小窗
6. 桌面专属：系统通知、开机自启、托盘角标、拖拽文件上传、深链直达任务、快捷键
7. 「检查更新」：新版本提示 + 一键打开下载页

第 1–4 项**已经全部实现**（就是现在的 Web 工作台）；第 5–7 项是桌面端独有、需要写代码的部分。

## 3 三条路线与取舍

### 路线 A（推荐）· 壳内嵌平台工作台 + 运行时可配服务器地址
主窗口 `BrowserWindow` 直接加载工作台（默认 `https://synapforge.top`，首次运行向导里可改成自托管地址），
配 `persist:synapforge` 分区持久化登录态；托盘/内核面板/深链仍是本地能力。

- **优点**：功能立刻 100% 对齐（同一套前端）；**前端永远最新**（改完服务器即生效，不用重发安装包）；改动量最小（主进程 + 菜单 + 通知 + 向导）。
- **代价**：需要网络（平台本身是服务器端应用，脱网时只能看到"离线"页与内核状态）；工作台是"应用里的网页"，不是原生控件（视觉上与浏览器一致，但去掉了地址栏/标签页）。
- **关键技术点（已验证）**：Electron 顶层加载不受站点 `X-Frame-Options`/`frame-ancestors` 限制；WS 推送（`/ws/projects/{id}?token=`）在渲染进程可用；登录令牌放应用持久分区即可跨启动保持。

### 路线 B · 自带前端副本 + 运行时可配服务器
把 `next build` 的静态产物打进安装包（`output: "export"`），客户端用本地文件加载自己的 UI，API 地址运行时可配。

- **可行性已验证**：前端是**全静态**的——25 页全部 `○ Static` 预渲染、无 `route.ts`、无 server actions、无 `next/image`/`next/font`，22 个页面是 `"use client"`。静态导出几乎零阻力。
- **唯一的改造点**：`apps/web/lib/api.ts` 的 `API_URL` 现在是**构建期**注入（`NEXT_PUBLIC_API_URL`）。桌面端要"装完再填服务器地址"，必须加一层**运行时覆盖**（preload 注入 `window.__SYNAPFORGE__ = { apiUrl }`，`api.ts` 优先读它、回落构建值）。
- **优点**：客户端不再依赖服务器的前端；可指向任意/自托管实例；离线时界面至少能打开并给出明确提示。
- **代价**：**前端每次改动都要重发安装包**（否则客户端 UI 落后于服务器）；产物与版本兼容要自己管（前端 ↔ API 版本检查）。

### 路线 C · 本地平台（离线可用，服务器降级为同步对象）
sidecar 里跑 FastAPI + SQLite，桌面端离线可用，联网再与服务器同步。

- **不建议**：平台是**多人协作**的服务器端应用（SQLite 单写者、项目权限、事件序号、门禁人工批准），
  本地化等于把产品变成另一个形态：多源真相、同步冲突、权限重做、离线批准算不算数……工程量与风险都远超"客户端"本身。
- 如果确实要"个人离线版"，应该作为独立产品线立项，而不是塞进这个客户端。

**推荐**：**A 起步**（1 期就有完整功能），B 的"运行时可配地址"作为 A 的一部分先做（让客户端能连自托管/局域网实例）；
B 的"自带前端副本"留到真有"客户端独立于托管前端"的需求时再做（§7 第 1 问）。
C 不做（写明边界）。

## 4 分期与验收

### D-1 外壳与工作台（1 期，最小可用）
- 主窗口加载工作台（默认线上地址，向导可改）；应用菜单（文件/视图/窗口/帮助 + 常用快捷键：刷新、前进后退、放大、开发者工具、打开内核面板）；外链一律外部浏览器打开；下载走系统下载（成果物导出、安装包）；
- 离线页与自动重连提示；窗口尺寸/位置记忆；托盘「打开平台工作台」改为**开窗口**，不再开浏览器；
- **验收**：装完 → 首次运行向导（地址 → 登录 → 配对设备）→ 窗口内完成"聊天 / 任务板 / 成果空间 / 设备页"四件事；
  断网时显示离线页并自动重连；关窗不退出、托盘可唤回。

### D-2 桌面专属能力（2 期）
- 系统通知（派给我的任务、待我复核、预算/证据告警）、托盘角标（我的待办数）、开机自启开关；
- **本机内核面板并入主窗口**（侧栏"本机 Agent"：连接状态、可用执行体、执行中任务、日志、暂停/紧急停止，复用现有 IPC）；
- 拖拽文件到聊天/云盘（走既有上传接口）、深链 `map://task/<id>` 直达、全局快捷键（快速跳转/搜索）；
- **验收**：任务派到我 → 系统通知点击直达该任务；拖一个文件进聊天框上传成功；内核面板能在主窗口里暂停/恢复领取。

### D-3（可选）自带前端副本 + 版本兼容检查
- `output: "export"` 打包前端产物；运行时地址注入；前端/API 版本握手（不匹配时提示升级客户端或服务端）；
- 只在 §7 第 1 问选 B 时做。

### 打包与发布口径（沿用既有经验）
- 重建：`scripts/build-desktop.ps1`（PyInstaller sidecar + electron-builder）；electron-builder 连 GitHub 超时就 `cd apps/desktop && npm run build:win` 走缓存；
- 发布：安装包放服务器 `/downloads/`（nginx `location ^~ /downloads/` 直出），平台内 4 处下载入口已就位；
- 版本号：`apps/desktop/package.json` 的 `version` 升到 0.2.0（这次是形态变化，不是补丁）。

## 5 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 未签名安装包 | SmartScreen 首次提示 | 已知边界；界面上写清"更多信息 → 仍要运行"；签名需证书与预算（§7 第 3 问） |
| 应用内是"网页" | 用户可能觉得不如原生 | 去掉浏览器痕迹（无地址栏/标签页）、加应用菜单与快捷键、原生通知/托盘/深链；这也是 VS Code、Slack、Discord 的做法 |
| 路线 B 的前端版本落后 | 客户端 UI 与服务器 API 不匹配 | 只在选 B 时做版本握手；A 路线无此问题 |
| Electron 体积与内存 | 安装包 ~150MB、常驻 ~200MB | 已知；托盘常驻是产品需要（后台干活），窗口关闭时释放渲染进程 |
| 内核与壳的版本错配 | 新旧 sidecar 契约不符 | 契约 v1 已有 `contract` 字段校验（`main.js:100`），保持不动 |

## 6 明确不做

- **本地平台/离线数据同步**（路线 C）——要另立项，不是客户端的事；
- **代码签名与静默自动更新**（默认不做；若拍板要走，需要证书 + electron-updater + 签名流水线）；
- **多服务器多账号并行**、**多窗口**、**原生自绘 UI**（重画 25 页，维护成本翻倍，收益低）。

## 7 待拍板（三项，均已给推荐）

1. **客户端形态**：A 内嵌远程工作台 + 可配地址（推荐）/ B 自带前端副本 / C 本地离线平台（不建议）
2. **桌面专属能力范围**：系统通知、开机自启 + 托盘角标、拖拽上传、内核面板并入主窗口、全局快捷键 + 深链（默认全要）
3. **更新方式**：检查更新 + 提示下载（推荐，无需证书）/ 暂不做 / 代码签名 + 静默自动更新（需证书与预算，另议）
