## 2. 开放邮箱注册（注册即用）

- **后端**：`store.register_account(…, allow_open_registration=)`。三种路径：
  ①首个账号免码成为管理员（优先级最高，与开放与否无关）；②带邀请码→按码上的角色；
  ③**无码开放注册→contributor**，并沿用"受邀成员自动加入组织内现有项目"的行为——
  这样新队友注册完就能看到项目（包括演示项目），而不是空列表。
- **开关**：`PLATFORM_OPEN_REGISTRATION`（**默认开**）。想回到邀请码模式：systemd 环境里设 `0`。
  注意口径写在代码注释里：开放注册=任何能打开网址的人都能注册并看到组织内项目——
  公网部署不想公开内容时要关。
- **前端**：注册页邀请码改为"可选，带指定角色"，文案写明"填邮箱与密码即可加入，注册即用（暂不验证邮箱）"。
- **测试**：`test_accounts.py` 新增 4 项（免码注册→contributor+可登录+可见既有项目、
  开放模式下邀请码角色仍生效、关掉开关回到 `invite_code_required`、邮箱唯一性）。
  原有"第二个注册需要邀请码"等测试不受影响（store 层默认关，开关由路由层注入）。

## 3. /ask 侧栏会话管理美化

原来的会话行是通用 `list-item`（大图标块 + 每行两行文字），删除按钮常驻。改为 ChatGPT 式：

- 顶部「**新对话**」（实心近黑）+「检索」（描边）；
- 会话行**紧凑两行**（标题 + "对话 · N 条"），当前会话**左侧 2px 高亮条 + 浅灰底**；
- 删除按钮默认隐藏、悬停/选中时出现（触屏常显），删前仍有确认框；
- 检索会话与普通会话用小图标区分（书 / 气泡），不再用彩色 icon-tile。

## 5. 多 Agent 文档撰写演示

`scripts/deploy/_demo_doc_writing.py`（幂等，可重复执行）：用**真实 store 调用**串一个完整故事——
**不伪造任何数据**，每一步（领取、进度、运行、产出、提交、复核、交接）都走 Agent 真实使用的同一条代码路径，
所以聊天卡片、成果物、门禁、时间线全是真事件。

故事：队长安排**写手 Agent**与**复核 Agent**协作写《synapforge 平台使用指南》——
提纲（写手）→ 队长确认 → 初稿（写手）→ **交接单**（写手→复核）→ 复核意见（复核 Agent）→ 修订定稿（写手）→
**四次人工复核通过**。穿插队长的群聊发言叙述。落地数据：**4 条任务、4 份成果物、
42 条群聊（38 张卡片 + 4 句人话）、1 张交接单**。

新用户体验闭环：**注册（免码）→ 自动看到演示项目 → 工作区有引导面板 → 点"看演示"→
群聊里读完整协作故事**。

## 7. 边界

- **不验证邮箱**（用户口径"暂时不用"）：任何人填个能收信的格式就能注册；没有邮箱确认、没有域名白名单。
  想收紧时：`PLATFORM_OPEN_REGISTRATION=0` 回到邀请码模式。
- **开放注册的成员是 contributor 且自动加入所有既有项目**——团队透明的既定口径，也意味着"内部项目"
  对任何注册者可见；多租户隔离仍是未实施项（见 `docs/MULTI_TENANT_DESIGN.md`）。
- **引导面板只出现一次**（localStorage 按浏览器记），没有分步向导/高亮遮罩式 tour；
  演示项目属于首位管理员，其它人只读地看（contributor 能看全群聊与成果）。
- **演示是静态剧本**：Agent 动作是种子脚本预先走的真实流程，不是持续运行的活 Agent——
  真正让 Agent 动起来仍需接入（引导面板第 2 步指向那里）。
- /ask 会话**没有重命名**、回答不是流式（既有边界延续）。
