## 1 思考块做了什么（已上线）

- **内核**：`run_serve_turn` 把 `reasoning` 段的增量按新事件 `thinking` 发出去——与 `delta` 同一套纪律
  （**绕开 reporter**、0.8/1.2s 节奏、**封顶后收尾补发、不丢字**）；`process.exited` 里带 `thinking_events` 便于对账。
  思考与正文**严格分开**：类型从 `message.part.updated` 的 `part.type` 学（S-2 踩过：两者的 `field` 都是 `text`）。
  CLI 回退通道也认（`part.type == "reasoning"` 的 `text` 事件同样进 `thinking`）。
- **页面**：抽屉里一个「思考过程」折叠块（默认收起，显示"224 字，点一下展开"）；等思考时状态文案写
  **「思考中（还没开始写正文）」**；`thinking` 与 `delta` 都不进"过程事件"列表（否则刷屏）。
- **线上实测**（生日问题那一轮）：抽屉里 224 字推理原文可见；气泡里只有答案
  （`约 70.6%（1 − 365×364×…×336 / 365³⁰ ≈ 0.706）…`）；事件表 `thinking×5 / delta×4`；
  `process.exited` = `{"delta_events":4,"thinking_events":5,"unknown_deltas":0}`；
  **全库回答里混进思考的轮次数 = 0**。

## 3 强度（`--variant`）：为什么**没上**（探针证据）

| 通道 | 实测 | 结论 |
| --- | --- | --- |
| CLI（`opencode run --variant <v>`） | `high` / `minimal` / `default` / `max` 都 exit=0；同一道题 `minimal` vs `max` 的 token 画像不同（total 7,514 vs 15,050） | 参数**被接受**，且请求确实不同；但 `reasoning` token 数并不随"强度名"单调（86 vs 42）——语义由厂商解释，页面不能替它保证"更努力" |
| serve（`message.model.variant`，**线上默认通道**） | 发消息 HTTP 200，**但回读会话仍是 `model.variant = "default"`**（v1 与 v2 两条读接口一致） | **静默无效**——正是"设了没生效"那一类坑（模型切换以前也这样骗过人） |

还给自定义 provider 的模型加 `variants` 声明试过一条路（怀疑"没声明就被忽略"），但探针把配置写成了非法形状、没验成——
那条路需要重新探（且要动执行体的 0600 配置），**不在没证据的情况下上**。

**没上不等于不做**，两条可选路（等用户定）：
1. **只做 CLI 通道的强度**（在页面上明确标注"仅回退通道生效"）——诚实但线上基本用不到；
2. **继续探 serve 侧**（配置声明 `variants` 的正确形状 / opencode 是否支持会话级 variant）——探通了再上，页面文案才敢写"生效"。

## 4 顺手抓到并修掉的两个真问题

1. **中间列横向溢出（前端真 bug，已修）**：`.my-agent-main` 与它的 `.panel` 缺 `min-width: 0`（flex/grid 子项默认
   `min-width: auto` = 内容最小宽度），对话里出现宽内容（长代码块/宽表格/选择卡）时把中间列**撑到 1353px**（容器只有 708px），
   页面横向溢出、输入框与发送键跑到视口外——表现就是"点不着、打不进字"（我自动化时先撞上的就是它）。
   修法：两处补 `min-width: 0`（注入验证通过：溢出消失、composer 回到 641px）。
   **这个仓库里同类坑踩过不止一次**（flex 子项缺 `min-width:0` 顶出横向滚动条）。
2. **设备项目授权过期导致对话通道中断（运维事件，已处置）**：`device-cloud-01` 的三条项目授权都是 **24 小时 TTL**
   （平台 `expires_in_seconds` 默认 86,400，`/devices` 页面授权时不传 → 用默认），最后一条 04:38 到期后：
   - 执行体每 5 秒 `claim -> 401 device_project_token_expired`（**对话通道实际已断**，页面只是"发出去没人接"）；
   - 新建会话报 `device_project_grant_missing`（裸错误码，用户看不出该去做什么）。
   **处置**：生成新授权（30 天上限，含 `chat.run` 全套能力）→ 执行体 `--grant-only` 应用 → 重启 → 恢复
   （设备 active、无 401、新建会话成功）。
   **设计缺口（留给用户定）**：24h 到期没有提醒、也没有续期入口的提示。建议二选一：
   ①授权时可选有效期（7/30 天）+ 设备列表显示"授权将于 X 后过期"+ 到期一键续期；
   ②心跳时若授权将过期则自动延长（方便，但削弱了 TTL 的本意）。**默认值我倾向 ①**。

## 5 边界与已知

- 思考块只在抽屉里（默认收起）——与 M-5b 计划里的"右栏思考块"一致；气泡里不显示思考（避免长篇推理挤掉答案）。
- `--format json` 回退通道的思考只有执行体真发了 `reasoning` 段才会出现（模板没带 `--thinking`，所以回退通道一般没有思考）。
- 抽屉展开时有一层 `.my-agent-backdrop` 遮罩：此时点左栏的「新对话」只会收起抽屉（第二次点才生效）——预期行为，自动化时注意。
