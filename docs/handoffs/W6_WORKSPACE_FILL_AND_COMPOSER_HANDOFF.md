## 1. 布局：聊天 Tab 铺满一屏，左右等高

问题有两个根因：

1. **这一页此前没有 `.page-content` 包裹**（返回的是裸 fragment），所以它既没有其它页的留白，也不在"内容区可滚动"之外——W-1 给聊天流设了 `max-height: 46vh` 的固定上限，于是下方空出一大片。
2. 右栏是三个 Panel 自然堆叠，高度由内容决定，于是比左栏还长。

改法（全部在 CSS + 页面容器）：

- 页面套上 `<div className="page-content" data-page="workspace">`，与 team / review 等页一致。
- **应用骨架改为"内容区自己滚"**：`.main-area { height: 100dvh; overflow-y: auto }`。顶栏是 sticky，仍在框内；侧栏本来就是独立滚动。这样"一屏正好装下的页面"就不用再靠 `calc(100vh - Npx)` 猜偏移量。
- 聊天 Tab 时给网格加 `is-fill`：左栏 `.panel` 撑满剩余高度、`.chat-stream` 内部滚动、输入区钉在底部；右栏 `align-items: stretch` 与左栏**等高**、内部滚动，最后一个 Panel 拉伸到底（两栏底边对齐）。
- **窄屏（≤980px）撤销铺满**：两栏改成上下堆叠后，固定高度会把聊天流压成一条缝（实测 8px）——所以那段媒体查询把 `flex` 约束全部退回自然流，页面照旧整体滚动。

实测（1280×900）：左栏 611px、右栏 611px、底边都在 y=870，页面不滚动，聊天流内部滚动。
手机（390×844）：聊天流 405px、无横向溢出、页面整体滚动。

## 2. 输入框：附件 + @成员 / /Agent

**附件**（`上传文件`）：浏览器文件选择 → `POST /api/drive/upload`（个人云盘，200MB 上限）→
`POST /api/projects/{id}/drive/import`（进本项目成果物）→ 发一条消息「已上传「文件名」（已加入本项目成果物库）」，
消息上带 `ref_artifact_id`，气泡里出现「查看成果物」跳转。

后端配套（本轮唯一的后端改动）：`ProjectMessageCreate.ref_artifact_id`（可选 UUID）+
`store.post_project_message(..., ref_artifact_id=)` 会校验**该成果物属于本项目**，否则
`message_artifact_not_in_project`（409）——消息里挂别人项目的对象属于越权引用。

**提及**：输入 `@` 或 `/` 弹出候选（光标前未打完的 `@xxx` / `/xxx` 触发；↑↓ 选择、Enter/Tab 确认、Esc 取消；
也提供 `成员` / `Agent` 两个按钮直接把触发符打进输入框）。成员候选带角色与待办数，Agent 候选带归属人、
在线状态与"正在跑什么"。插入后是纯文本 `@名字` / `/名字`，消息里渲染成浅底高亮（只认名单里存在的名字，
避免误伤普通文本）。

**明确的口径**：提及用于**点名与留痕**，**不会自动派活**——Agent 读不到聊天（`agent_protocol` 是禁区），
派活仍然走「任务」Tab 的派单。这条也写在输入框下方的提示里，避免队友误解。

## 4. 边界（明确没做）

- **原生文件选择框无法被自动化驱动**（IAB 能力边界）。按钮本身（计数/可用/文案）与它背后的三步链路
  （上传→导入→带引用发消息）分别验过，但"点按钮 → 选文件"这一下需要人手动点一次确认。
- **上传走个人云盘配额**（200MB/人）：大附件会被拒（`drive_quota_exceeded`）；文档也写在提示里。
- **提及不触发通知**：平台没有通知系统，被点名的人只会在群聊里看到自己的名字高亮。
- **@ 只列项目成员、/ 只列本项目已授权的 Agent**；跨项目的人/机器不在候选里。
- 附件只支持单文件（每次一个），没有多选、没有拖拽上传、没有进度条（上传中是按钮上的转圈）。
