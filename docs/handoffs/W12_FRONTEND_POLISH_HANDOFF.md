## 2. 现状证据与设计判断

### 2.1 设计系统现状

`globals.css` 已有以下令牌：

- `--bg`、`--surface`、`--surface-muted`、`--border`。
- `--accent`、`--green`、`--amber`、`--red`。
- 6/10/14px 圆角和轻量阴影。
- 亮色与暗色主题覆盖。

当前方向是可用的，不要把它改成彩色营销页、渐变仪表盘或大面积插画风。

### 2.2 主要问题

1. 首页从“下一步”到指标、进度、门禁、快捷入口、运行状态、交接和事件，多个区域权重接近，首屏主任务不够突出。
2. `/my-agent` 在 `max-width: 900px` 时隐藏 `.ask-sessions`，但没有替代的会话抽屉入口，窄屏用户无法方便切换历史会话。
3. `/my-agent` 已有流式内容和执行细节，但“正文、思考、工具调用、等待权限、产出文件”的视觉语义还不够区分。
4. 普通页面大量使用同一类 `.panel`，容易产生“面板堆叠”感。
5. 顶栏同时承载面包屑、快速跳转、项目切换、同步状态、刷新、主题、账号等控件，窄屏和中等宽度下容易拥挤。
6. 现有动画包含骨架、旋转、脉冲和抽屉过渡，但未看到统一的 `prefers-reduced-motion` 适配。
7. 通用 `Modal` 有 dialog 语义，但需要补齐 Escape、焦点进入、焦点返回和背景滚动处理。
8. 导航快速跳转仍有历史深蓝硬编码，和当前黑白灰设计令牌不完全一致。

## 3. 本批目标与非目标

### 3.1 目标

- 让用户进入首页后能快速找到“当前最重要的下一步”。
- 让窄屏用户可以打开、切换和删除智能体历史会话。
- 让流式智能体回答清楚区分正文、过程、工具调用、等待权限和文件产出。
- 让工作区、任务页、审核页的状态更容易扫描。
- 减少普通面板的视觉噪声，保留抽屉、弹窗等浮层的层级。
- 统一动效、键盘交互和减少动态效果支持。
- 不破坏现有 API、WebSocket、任务、成果物、审核和 Agent 协议。

### 3.2 非目标

本批不做以下事项，除非用户另行确认：

- 不升级依赖、不更换 UI 框架、不引入新的 CSS-in-JS 方案。
- 不重写后端接口、数据库模型、Agent 协议或 WebSocket 契约。
- 不删除既有路由、旧版 `/ask` 或深页能力。
- 不把只读页面改成写入页面。
- 不批量重命名组件、路由或测试 ID。
- 不把 Web 改成大面积紫色、蓝色、渐变或营销型 Landing Page。
- 不增加未经验证的“自动执行”“自动批准”“自动重排任务”等产品承诺。
- 不用动画代替状态文字，不模拟不真实的逐字输出。
- 不以截图好看为理由改变现有权限边界或数据语义。

### W12-01 首页总览重排：突出当前推进

**优先级：P0**

**涉及文件：**

- `apps/web/app/page.tsx`
- `apps/web/app/globals.css`
- 必要时复用或小幅扩展 `apps/web/components/ui.tsx`

**实施要求：**

1. 保留现有项目无数据、未选择项目和正常项目三种状态。
2. 将首页首屏视觉重点集中到“当前推进”区域：
   - 当前项目和阶段；
   - 当前最重要的下一步；
   - 一个明确的主操作；
   - 当前阻塞原因或等待条件。
3. 不要同时把“项目工作区、模板包、下一步”做成三个等权重主按钮。保留一个主操作，其余降为次级操作或链接。
4. 四个指标保留数据含义，但视觉上可收紧为状态摘要栏或低高度指标区，不要继续放大为四个主卡片。
5. 进度、任务、门禁、风险作为主要工作内容优先展示。
6. 交接、最近事件、快捷入口、运行状态等信息可以保留，但降低层级或放到第二屏，不得删除已有入口。
7. 首页中的文案必须如实反映后端状态，不能把“等待 Agent 领取”写成“正在执行”。

**验收条件：**

- 1440px 宽度首屏能在 5 秒内找到当前主任务和主操作。
- 1280px 宽度下首屏没有明显的顶栏或标题操作挤压。
- 首页不出现 6 个以上同等视觉权重的主面板。
- 没有项目、无 Agent、无任务、存在风险、任务已完成等状态均能正常显示。
- 不改变首页已有跳转目标和数据统计口径。

### W12-03 智能体流式执行状态层级

**优先级：P1**

**涉及文件：**

- `apps/web/app/my-agent/page.tsx`
- `apps/web/components` 下已有智能体回答/Markdown/事件相关组件

**实施要求：**

3. 为过程信息提供可折叠区域，默认显示简短摘要，例如：
   - `思考过程 · N 个步骤 · 用时`
4. 工具调用和文件产出使用紧凑事件行或时间线表达，例如：
   - 已读取数据文件；

   - 正在生成图表；
   - 已生成结果文件。
5. 明确区分以下状态：
   - 准备中；
   - 思考中；
   - 执行中；

   - 失败，可重试。

- 流式生成中，用户能分辨“正文”和“执行过程”。
- 过程事件多于 10 条时不会把对话区刷满，默认摘要或折叠有效。

- 流式输出时页面不会出现横向滚动或持续跳动。
- 用户向上阅读时不会被新内容强制拉回底部。
- 断线、失败、无内容和用户选择卡片状态仍能正常呈现。

### W12-03A 动态效果与交互反馈规范

**优先级：P1**

本项不是给页面增加装饰动画，而是让用户能感知“发生了什么、正在等待什么、下一步能做什么”。所有动态效果都必须服务于状态变化；没有状态变化时不要持续运动。

**涉及文件：**

- `apps/web/app/my-agent/page.tsx`
- `apps/web/app/workspace/page.tsx`
- `apps/web/components/shell.tsx`
- `apps/web/components/ui.tsx`
- `apps/web/app/globals.css`

#### 1. 动效基线

统一使用短、克制、可中断的过渡：

| 场景 | 建议时长 | 建议效果 |
| --- | ---: | --- |
| hover/focus 背景变化 | 120-160ms | `ease-out`，只改变背景、边框或颜色 |
| Tab 切换 | 160-220ms | 活跃指示条或背景平滑切换，不移动整页内容 |
| 抽屉打开/关闭 | 180-240ms | 横向位移 + 遮罩透明度变化 |
| Modal 打开/关闭 | 160-220ms | 轻微位移/透明度，不使用缩放弹跳 |
| Toast 出现/消失 | 180-240ms | 从底部轻微上移，不遮挡主要输入区 |
| 进度变化 | 300-500ms | 只过渡进度条宽度，不反复闪烁 |
| 新消息进入 | 120-180ms | 轻微透明度/位移，禁止整段列表重排动画 |

不要使用无限循环动画表达普通静态状态。旋转只用于明确的处理中状态，脉冲只用于在线或实时更新提示，并且必须有文字说明。

#### 2. 页面进入与内容加载

1. 页面首次加载使用已有 `LoadingSkeleton`，骨架行只做低频明暗变化，不做左右扫光。
2. 数据加载完成后，内容直接稳定出现；不要让每一张卡片依次从不同方向飞入。
3. 首次进入首页时，主操作区域可以有一次轻微的边框/背景强调，但最多播放一次，不能循环。
4. 数据刷新时保留已有内容，使用顶栏刷新按钮的短暂旋转或局部状态文字；不要整页白屏再重新出现。
5. 请求失败时使用错误区域或 Toast，错误区域出现后不应把用户当前正在阅读的内容强制滚走。

#### 3. Tab、筛选和折叠

1. 工作区 Tab 切换时只更新内容区域，Tab 本身保持在视口内。
2. Tab 活跃状态使用背景、文字和底部指示，不做大幅横向滑动。
3. 任务筛选、审核筛选和事件筛选切换时，结果区域可以使用 120-160ms 的淡入，但禁止逐行重新飞入。
4. 折叠思考过程、候选执行体、辅助面板时使用高度/透明度过渡；内容较长时必须允许用户立即中断并再次点击。
5. 折叠状态需要保存在当前页面会话中，但不应偷偷改变用户已经选择的筛选条件。

#### 4. `/my-agent` 流式交互

1. **发送消息**：发送按钮进入 `发送中` 状态，防止重复提交；请求确认后恢复为可发送或进入 `停止生成` 状态。
2. **流式输出**：正文按真实增量追加，不做逐字打字机动画；当前生成位置可以显示一个低调光标或状态点。
3. **思考过程**：默认折叠，标题显示步骤数或已用时间；展开/关闭必须是用户主动操作，不自动抢焦点。
4. **工具调用**：开始时显示 `执行中` 状态点，完成后转为静态勾选，失败显示失败图标与“重试/查看详情”入口。
5. **等待用户选择**：停止脉冲动画，显示明确的选择卡片；用户选择后卡片锁定并显示已选择内容，避免重复点击。
6. **等待权限**：显示“等待授权”及下一步操作，不要使用看似正在运行的旋转图标误导用户。
7. **新内容未贴底**：用户向上滚动时暂停自动滚动，在输入区上方或消息区底部显示“有新回复”提示；点击后平滑回到底部。
8. **停止生成**：停止按钮有明确的按下反馈；停止后显示“已停止”，不能把部分回答标记为“已完成”。
9. **失败重试**：重试按钮只重试失败轮次，不清除已有历史消息；重试中显示局部加载状态。
10. **文件产出**：文件生成完成时显示一次轻微高亮或 Toast，并把文件行保持为可操作静态状态，不持续闪烁。

#### 5. 工作区聊天与任务动态

1. 新消息到达时只对新增消息做一次轻微入场效果；历史消息不得全部重新播放。
2. Agent 在线/离线变化使用状态点颜色变化和文字变化；在线脉冲最多用于实时连接状态，不用于普通列表每一行。
3. 任务从 `READY`、`RUNNING`、`WAITING_REVIEW`、`DONE` 等状态变化时，状态徽标和左侧状态边线平滑切换；标题、负责人和整行位置保持稳定。
4. 任务被阻塞时只强调状态和下一步，不让整行持续抖动或红色闪烁。
5. 新任务、成果物和审核事件可以使用 Toast 或一行系统事件提示；Toast 不能遮住输入框，且同类事件需要合并，避免高频刷屏。
6. 批量操作时显示“已选择 N 项”和确定中的局部进度；不要在每一行同时显示多个旋转图标。

#### 6. 抽屉、Modal、Toast 与菜单

1. 抽屉打开：先显示遮罩，再让抽屉在 180-240ms 内滑入；关闭时反向执行。遮罩点击和 `Escape` 都要立即可用。
2. 抽屉打开后背景内容保持位置不变，不产生页面横向滚动。
3. Modal 打开时焦点进入 Modal；关闭后焦点返回触发按钮，动效不能延迟键盘可用性。
4. Toast 从底部进入，默认停留时间不超过 4 秒；错误和需要用户处理的消息不能只靠自动消失。
5. 账号菜单、快速跳转等浮层使用短暂透明度/位移过渡；点击外部区域关闭时不要延迟。
6. 菜单、抽屉和 Modal 层级不能互相覆盖错误；确认操作必须在视觉上位于当前上下文之上。

#### 7. 拖拽、上传和网络状态

1. 文件拖入聊天区时，整个可接受区域出现一次边框高亮和“松开以上传”提示；离开区域立即恢复。
2. 上传中显示文件级进度或处理中状态，禁止只显示全局无限旋转。
3. 上传成功转为附件 chip；失败保留失败文件和重试/移除入口，不清空用户其他附件。
4. WebSocket 断开时，连接状态从“已同步”过渡到“重连中”，恢复后显示一次“已恢复同步”；不得把断线误显示为数据为空。
5. 离线或重连期间仍可阅读已有内容，禁止因为连接状态变化整页闪烁。

#### 8. 动效实现限制

- 优先使用 CSS `transform`、`opacity`、`background-color`、`border-color`，避免对大列表使用高成本布局动画。
- 不对 `height: auto` 做不稳定动画；必要时使用明确的最大高度或 CSS grid 行过渡。
- 不给每个 delta、每条历史消息或每个任务行添加独立定时器。
- 不在组件卸载后继续触发状态更新或动画回调。
- 动画期间仍必须可点击、可键盘操作、可关闭；不要用动画结束作为功能可用的前置条件。
- 动效失败或被浏览器禁用时，静态状态必须完整可理解。

#### 9. 动效验收条件

- 首次进入页面不会出现大面积卡片依次飞入或整页闪烁。
- 流式回答、思考、工具调用、等待选择、等待权限、失败和完成状态可明显区分。
- 新消息不会造成历史列表整体跳动。
- 用户向上阅读时不会被自动滚动打断。
- 抽屉、Modal、Toast、菜单均可在动画尚未结束时通过键盘或点击关闭。
- 高频事件下页面不会持续闪烁、卡顿或产生大量重复 Toast。
- 开启 `prefers-reduced-motion` 后，动画被缩短或移除，但状态文字和操作能力不丢失。

### W12-06 弹窗、抽屉与动效可访问性

**优先级：P1**

**涉及文件：**

- `apps/web/components/ui.tsx`
- `apps/web/app/globals.css`
- 抽屉组件或使用抽屉的页面

**实施要求：**

1. `Modal` 支持 `Escape` 关闭。
2. 打开时将焦点移动到关闭按钮、标题或首个可操作控件。
3. 关闭后焦点返回触发按钮；如果无法完整实现焦点返回，至少不要让焦点丢失到页面顶部。
4. 弹窗打开时禁止背景页面滚动，关闭时恢复原状态。
5. 抽屉支持 Escape、关闭按钮和遮罩点击。
6. 危险确认框不能仅依赖颜色表达危险，保留明确的动作文字。
7. 为旋转、脉冲、骨架闪烁、抽屉滑入、进度过渡增加统一的 `prefers-reduced-motion` 规则。
8. 动效关闭后，状态仍通过文字、图标、颜色和结构表达。

建议的基础规则：

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

**验收条件：**

- 键盘可完成打开、关闭和确认/取消弹窗。
- 弹窗或抽屉打开时 Tab 不会跑到背景主要内容。
- `Escape` 行为不会误触发页面级导航或提交。
- 开启系统“减少动态效果”后，页面没有持续闪烁或无意义旋转。
