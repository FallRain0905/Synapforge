# 「我的智能体」体验四改：固定高度 · 输入区重做 · 产出文件可下载/转云盘

> 2026-09-24 · 状态：**四项全部上线并实测** · 上游：M-1…M-6、M-5c S-0/S-1/S-2（对话通道 / 常驻 serve / 增量）
> 用户原话四条：① 对话区固定长度、内部滚动（不要越聊越长把顶上模式与模型按钮顶走）② 上传按钮的图标太小
> ③ 仿 zcode 的输入区（「+」展开添加面板 + 下方一排控件）④ 生成的文件要能**直接下载**或**转入云盘**

---

## 1 四项各自怎么落的

### ① 对话区固定高度 + 内部滚动（真因是 grid 行的下限）

量到的真因：`#my-agent` 是 grid，行写的是 `auto minmax(0, 1fr)`（前一天为修"下方空白"改成 `minmax(min-content, 1fr)`），
而 **`min-content` 的下限就是整段内容的高度**——6 轮对话时第一行被撑到 **7709px**，页面整体滚动，顶部工具栏被顶出视野。

修法：`#my-agent { grid-template-rows: minmax(0, 1fr) auto; }` + `.my-agent-layout { grid-template-rows: minmax(0, 1fr); }`
（**每一级都要能被压缩**，否则滚动还是跑到页面级）+ `.my-agent-work-view { overflow-y: auto; }`（工作模式自己滚）。
线上实测（1280×860，同一屏）：`.main-area` 不再滚动、`.ask-messages` 内部滚动、工具栏 top=115 常驻可见。

> 这一格 CSS 前后踩了三次，注释里三段都留着：`auto` 给空行 → 下方空白；`min-content` 当下限 → 页面越聊越长；现在是 `minmax(0,1fr)`。

### ②③ 输入区仿 zcode 重做

- 输入区变成**一张卡片**：上面写内容，下面一排控件（`[+ 圆形加号] [角色▾] [附件 n] [模型▾] [↑ 发送]`）；
- 「+」展开**添加面板**（浮在卡片上方、可滚动）：`附件`（一行：图标 + 名称 + 一行说明）→ `角色（改完对下一轮生效）`（默认 + 12 个角色，各带说明，可执行角色标「（可执行）」）→ `执行体`（名称 + 在线状态，点开右侧执行细节）；
- 点面板外或按 Esc 收起；图标从 14 加大到 17–18（用户反馈"太小不美观"）；
- **模型与角色从顶部工具栏挪进控件行**（工具栏只留"这一轮跑在哪台执行体"与如实标注的动手权限），顶部因此不再拥挤。

### ④ 产出文件：上传成成果物 + 「下载 / 转入云盘」

三层，每层一个明确口径：

| 层 | 做了什么 | 关键决定 |
| --- | --- | --- |
| 内核 `apps/agent/chat_outputs.py`（新） | 执行前记工作区快照、执行后差分，把**新出现/被改过**的文件建成成果物并上传 | **没有 Run**（`run_id=None`，直接挂项目）；幂等键按轮次算 `artifact-create:chat:{turn_id}:{sha(路径+内容)}`（同路径不同轮次各成一份，不会判冲突）；`inputs/`、`__pycache__`、日志等**不算产出**；单文件 64MB、单轮 20 个上限（超了只登记不上传）；**上传失败不改这一轮成败**（与 CL-1 的 I4 同一口径） |
| 平台 | 迁移 `026_agent_turn_outputs.sql`（`agent_turns.outputs`）+ 契约 `AgentChatTurnOutput` / `AgentChatTurnComplete.outputs` / `AgentChatTurn.outputs` + 新端点 `POST /api/drive/from-artifact/{id}` | 产出与 `artifacts`（**输入**附件）分两列：语义相反，混在一起历史就分不清谁进谁出；成果物状态 `PENDING_REVIEW`——**对话通道也要过审核那道门**；「转入云盘」是**复制**（成果物留在项目里），去重与配额复用 `upload_drive_file`，并且**只有项目成员能取** |
| 页面 | 每轮回答下方一行「这一轮产出的文件（成果物，待审）」：名字 + 大小 + 「下载」「转入云盘」 | **下载走 `downloadArtifactContent`（带令牌取 blob）而不是 `<a href>`**——`lib/api.ts` 里早有这条注释：普通跳转不带 Authorization，强制鉴权下 401（我第一版就是 `<a href>`，已改） |

## 2 线上实测（2026-09-24）

- 布局：见 §1① 的数值；工具栏常驻、对话区内部滚动。
- 输入区：面板 16 行（附件 1 + 角色 13 + 执行体 1 + 标题），底部控件行 5 个控件，加号 32×32、发送 34×34 且都在卡片内。
- **产出闭环**：让它把 1–5 的平方写进 `notes/squares.md` → 页面上出现
  `squares.md 136 B [下载] [转入云盘]`；点「转入云盘」弹「已转入个人云盘」；云盘页文件数 3→4 且能看到它；
  点「下载」触发浏览器下载事件。**哈希对账**：执行体上 `sha256(notes/squares.md)` 与平台成果物的 `content_hash`
  都是 `b7473cb44b58851c74f516f04048234c2aeb585c28450ca7b24d3e9a5927c315`、`136` 字节、状态 `PENDING_REVIEW`。
- 清理：测试会话已删（用户自己的会话未动）、云盘里的测试文件已删（3→2）、执行体工作区的 `notes/` 已删。

## 3 顺手发现的两件事（不改，但要知道）

1. **换角色后模型可能"接着上一条拒绝"**：同一会话里把角色从「文献检索」换成「编程实现」，执行体日志显示
   `agent=mm-coding`（**协议层真的换了角色**），但模型因为上一轮自己说过"我是检索角色、不写文件"而继续拒绝。
   这是**模型行为**不是通道 bug；真要用新角色开新活，最稳的是**开一条新会话**（新会话 = 新 session = 干净的系统提示与历史）。
2. **成果物没有删除接口**：测试产出的 `squares.md`（PENDING_REVIEW）留在项目里——它挂在那一轮的产出清单上，
   删行会让页面上的下载按钮 404。要清理请在**审核页退回**它，或后续加一个"作废成果物"的正式入口。

## 5 边界

- 产出采集只覆盖**工作区里新增/改动的普通文件**：超大只登记、单轮上限 20 个、`inputs/` 与排除后缀跳过，都在 `CollectResult.note()` 里如实报。
- 「转入云盘」是复制，不做"移动"；云盘配额 200MB、同内容自动去重（复用既有链路）。
- 新会话会继承输入区当前的角色/模型选择——若想回到默认角色，先在「+」面板里切回「默认（无角色）」再开新会话。
