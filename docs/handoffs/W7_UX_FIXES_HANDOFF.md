## 1. 总览引导：模板包从"必经步骤"改为"二选一路径"

首页「下一步」向导原第二步是"应用模板包"，主按钮会把人引去物化——但模板包只是**推荐路径**，
不是必选项（用户可能只想让 Agent 写一份文档）。

- 步骤改为：**建项目 → 准备任务 → 接入 Agent → 让任务跑起来**；
- "准备任务"的完成条件只看**项目里有没有任务**（`dashboard.tasks.length > 0`），不看你有没有物化模板；
  提示文案写明两条路：「直接建自定义任务（让 Agent 写文档、查资料），或用模板包一键生成数模全流程」；
- 主按钮相应从「去应用模板包」改为「去准备任务」。

## 2. 自定义任务：工作区任务板的「新建任务」弹窗

后端本来就支持自由建任务（`POST /api/projects/{id}/tasks`，/tasks 深页也有表单），缺的是**显眼入口**和**引导口径**。
现在任务板右上角有「+ 新建任务」：

- 字段：标题（必填）、说明（给 Agent 看的要求）、阶段、优先级、负责人（可留空=先到先得）、截止时间；
- 弹窗副标题直接写口径："自定义任务不依赖模板包：给 Agent 安排任何活（写文档、查资料、跑代码都行）"；
- 任务板底部提示同步说明"模板包适合数模全流程，自定义任务适合让 Agent 写一份文档这类活"；
- 创建成功 → 任务出现在任务板顶部、群聊出现「创建了任务「…」」系统行（W-1 的事件桥自动派生）。

## 3. 消息卡片：系统事件降为一行小字，Agent 卡片收紧自适应

原问题：每张卡片都是"盒子"（徽章 + 时间 + 正文 + 链接，padding 8×12），
一条"创建了任务「X」"也占 60px 高——机器噪声比人话还显眼。

- **系统事件（建任务/派单/模式切换/复核结果…）不再有盒子**：一行 11.5px 灰字 + 时间 + 可点的"任务/成果物"小链接，实测 17px 高；
- **Agent 卡片收紧**：padding 5×10、字号 12.5、meta 行 10.5px，宽度 `min(76%, 620px)` 且**随内容自适应**；
- 人类气泡同步收紧。聊天流整体 gap 从 10px 降到 6px。

## 4. AI 问答（/ask）：ChatGPT 式布局

原来**会话列表在宽栏、聊天在窄栏**（第一子元素落在 1.6fr 主列），整个页面是"倒的"。重构后：

- **主区（宽栏）= 对话窗口**：铺满剩余视口高度（复用 W-6 的内容区滚动骨架）、消息内滚、输入区钉底，
  用户消息浅灰气泡右对齐、回答左对齐，来源（检索命中）挂 chips；
- **侧栏（窄栏）= 会话管理**：「+ 新对话」「检索会话」、默认知识库选择、会话列表（切换/删除，删除带确认）；
- **未选会话时直接输入**：自动新建一个「对话」会话（标题取问题前 18 字）再发送——像 ChatGPT 的"新对话即开聊"。
  检索会话需要绑知识库，仍显式新建；
- 窄屏（≤980px）不做铺满（对话在前、会话管理在后，页面自然滚动），与工作区同一套回退。

## 5. 过程中修掉的三个回归/缺陷

1. **/ask 首屏拿不到会话列表**：子组件 effect 先于 AuthProvider 恢复令牌执行，第一个请求不带
   Authorization → 401 → 侧栏恒空。加 `ready && authenticated` 门控后修复
   （复测：加载即显示既有会话；输入发送后自动建会话、气泡与回答都渲染）。
2. **自动建会话后乐观气泡被清掉**：建完会话就重拉列表会覆盖正在展示的用户消息。改为"带
   preferredId 只刷侧栏、不动消息区"。
3. （实测环境）本地开发库没配 LLM 凭据，回答是"请先在设置中配置 LLM 凭据"——这是**环境提示不是缺陷**，
   线上在「高级工具 · 空间设置」配置后即正常。

## 7. 边界

- 新建任务弹窗**不含**执行方式（codex/声明式命令）与输入成果物——这两个在 `/tasks` 深页的表单里，
  属于"把任务变成 Agent 能跑"的第二步（总览引导第 4 步会指过去）；
- /ask 的回答**不是流式**（一次性返回），也没有 Markdown 渲染与代码高亮——接口是同步问答；
- 会话**没有重命名**；检索会话的切换只在当前成员的会话里（会话按成员隔离，既有语义）；
- 系统事件的"一行小字"没有再细分成"重要/次要"两级（派单与复核这类需要留意的事件目前同级）。
