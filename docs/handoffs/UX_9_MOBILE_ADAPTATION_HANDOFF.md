## 2. 改动

**CSS 断点从两级重构成四层**（`apps/web/app/globals.css`）：桌面 ≥1101 / 平板 901–1100 / 小平板 761–900 /
手机 ≤760 / 小屏手机 ≤400。原先 1024px 就把多列压成单列，平板横屏浪费严重；现在平板保留
`.grid-main-side` 两栏、`.grid-3` 三列。

**移动端底部标签栏**（新组件 `components/mobile-tabs.tsx`）：总览 / 任务 / 审核 / AI 问答 / 更多（打开抽屉），
带任务阻塞与待审门禁的提醒点，≥761px 由 CSS 隐藏（桌面体验不变）；每项 ≥48px 触摸高度、
`safe-area-inset-bottom` 留白，`.page-content` 在手机上补 84px 底部内边距避免被遮挡。

**层叠顺序重排并修掉一个真 bug**：原先 `.sidebar`(70) 高于 `.modal-backdrop`(60)，从抽屉点「新建项目」
弹窗会被抽屉盖住。现在 标签栏 65 < 遮罩 69 < 抽屉 70 < 弹窗 80 < toast 85 < 快速跳转 90。

**抽屉补完**：遮罩层（点击关闭）、Esc 关闭、打开时锁 body 滚动、关闭态 `visibility:hidden`
（原先关着的抽屉仍在 Tab 顺序与无障碍树里）、`100dvh`、隐藏抽屉里的 "Ctrl K" 提示。

**表格与列表**：6 个表格页（tasks/artifacts/drive/devices/kb/graph）的单元格加 `data-label`，
≤760px 每行变卡片（标题 → 「阶段：xx」→ 操作按钮换行左对齐）；把重复的内联对齐样式抽成
`.row-actions` / `.list-actions` / `.list-inline-actions` 三个类，桌面视觉不变、手机上才能改写对齐。

**页面定点修复**：`graph` 画布保持 560px 最小宽度靠横向滚动（缩到 328px 时节点标签只有约 6px 高）、
`ask` 手机上对话面板排到会话列表之前、`documents` 协作标题栏换行 + 列表限高、`settings`/`tasks`
表单网格单列、`timeline` 搜索框改百分比、`.toast` 限宽并抬到标签栏之上、`layout.tsx` 补
`viewport` 导出（`viewportFit: cover`，安全区域才生效；**不禁用缩放**）。

**触摸目标与 iOS 细节**：`.app-icon` 36px、`.button` 40px、行内次要操作 32px、导航项 12px 内边距；
`input/select/textarea` 在手机上 16px（iOS 聚焦时不再自动放大页面）。

## 3. 验证过程中修掉的四个真问题

都是"跑起来才暴露"的，不是理论风险：

1. **顶栏横向溢出**（全站级）：360px 下需要约 500px。根因是项目切换器的**内联** `minWidth: 180`
   盖过了媒体查询——改成 `.project-switcher` 类（桌面 180px 下限、手机上可压缩）。
2. **`.item-copy` / `.table-title` 的隐式网格列**按 max-content 撑开：`white-space: nowrap` 的长标题
   会把整行撑出容器（手机上横向滚动、桌面长标题同样存在）。显式声明 `grid-template-columns: minmax(0, 1fr)` 后
   `overflow: hidden + ellipsis` 才真正生效。
3. **长不可断字符串的文本溢出**：`/runs` 的运行摘要是长标识符，元素矩形都在容器内、只有
   `scrollWidth` 变大（我的溢出扫描器一开始没抓到）。给 `.list-item, .table-row` 加 `overflow-wrap: anywhere`。
4. **`.list-item` 在手机上写死两列**：`[文字][状态 pill]` 这类行会被挤成 0px 宽。改成
   "最后一个单元格（文字块除外）独占一行"，两种行结构都能正确落位。

另有一个测试自身的问题：`.profile-avatar` 在 ≤760px 被隐藏后，**手机上没有账号/退出入口**——
这既是测试受阻的原因，也是真实缺陷，于是在侧栏/抽屉底部补了账号入口（该修复随 AUTH-1 一起落地）。

## 4. 验收

- 构建 19 页（当时）通过；SSR 不变量（16 路由 × 16 导航入口 + 5 分组按钮 + 移动端标记 + viewport-fit）通过。
- **四视口（320×568 / 390×844 / 768×1024 / 1024×768）× 16 路由 = 64 组合的几何断言全部通过**：
  无横向溢出、手机档标签栏显示且每项 ≥48px、表格行单列且标签生效、chip/pill 文字不截断、
  ≤760 抽屉关闭态不可见、≥761 标签栏隐藏。
- 交互实测：抽屉打开有遮罩且锁定滚动、Esc 关闭并还原、标签栏跳转正确高亮、「更多」打开抽屉。
- 回归：API 330 项、Agent 281 项、`demo-1.0.ps1` 17/17、前端 19 页（本次未改后端与 Agent）。
- 截图留存：390 概览 / 390 任务（卡片式表格）/ 768 任务（平板两栏）。

## 5. 尚未完成与边界

1. **未做真机验收**：我没有手机，验收是"桌面浏览器四视口 + 几何断言 + 截图"。真机上的
   iOS Safari 地址栏收缩、Android 手势条、输入法弹起等行为需要人眼确认一次。
2. 不做 PWA / 离线（用户本轮未选）；`/graph` 的 SVG 缩放与拖拽平移不做，只保证可读可滚动。
3. 移动端底部标签栏固定 5 项（四页 + 更多），没有做成可配置。
4. 部分页面在手机上仍需较多滚动（documents 的编辑器、devices 的接入向导），这些是桌面工作流，
   只保证了"能用"，没有做移动优先的重新设计。
