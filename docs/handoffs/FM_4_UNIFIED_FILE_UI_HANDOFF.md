## 1 这一期做了什么

`/drive` 从"只有个人云盘的文件管理器"变成**统一文件管理界面**：左侧一列"位置"，
第一项是个人云盘，后面是每个已接入的 Agent 工作区（云端/桌面都算），右侧是同一个浏览器形态。

**统一的是界面与操作语义，不是物理存储**——这句话在实现上是这样落地的：

| 维度 | 个人云盘 | Agent 工作区 |
| --- | --- | --- |
| 数据在哪 | 平台对象存储 | Agent 所在机器 |
| 列表怎么来 | 直接读（`/api/drive/nodes`） | **入队一个 `list` 操作 → Agent 执行 → 回报** |
| 写在什么时候发生 | 请求里立即发生 | 入队 → Agent 领取 → 执行（`queued→claimed→running→succeeded/failed` 全程可见） |
| 大文件 | 直传/直下 | 走 `file_transfer_sessions` + 对象存储 |
| 删除语义 | 进回收站（可恢复） | **不进回收站**（确认框里写明），受保护路径内核拒绝 |

界面上的差别只有"操作状态"这一处，而且是**如实**的差别（工作区那侧每个动作都带状态与错误码）。

## 2 关键实现

- `apps/web/app/drive/page.tsx`：左侧「位置」栏（云盘 + 工作区，带在线状态与"最后同步"），
  标题动作按来源切换；云盘那半边保持 FM-2 的全部能力。
- `apps/web/app/drive/workspace-browser.tsx`（新增）：工作区浏览器。
  - 每个动作 = `runWorkspaceOperation`（入队 + 轮询到终态），**不乐观改本地列表**；完成后重新拉目录；
  - **保护路径不给操作入口**：`.git`、`.math-agent-platform`、工作区根、Agent 自报的保护目录会渲染
    「受保护」徽标，并且**不显示**改名/复制/删除按钮（"无权限操作不显示为可执行"）；
  - **离线只读缓存**：最后一次成功读取的目录落在 `localStorage`，离线时显示它 + 「最后同步 X」，
    并且**不再往队列里塞注定失败的 `list`**；此刻发起的操作如实停在「排队中」，可取消，上线后自动执行；
  - 操作面板列出本次会话的操作（状态徽标 + 失败原因 + 失败可「重试」+ 排队可「取消」）。
- `apps/web/lib/workspace-files.ts`（并入 `lib/api.ts`）：工作区接口与 `runWorkspaceOperation` 轮询助手、
  传输会话（创建/写内容/读内容，哈希与大小由服务端校验）。
- `apps/web/app/drive/drive.css`：根栏、离线横幅、状态徽标、窄屏（≤900px 左侧栏收进「位置」抽屉）样式。
- 内核一处修正（FM-3 遗留）：`file_worker` 的 `list` 结果返回**生效的**保护清单
  （内置默认 `.git`/`.math-agent-platform` + 平台登记 + Agent 自报），否则页面会以为 `.git` 可删、
  点了却被内核拒绝——"显示为可执行但必然失败"是这里最糟的体验。

## 4 与计划的偏差 · 未做

- **工作区里的"移动"用输入相对路径**（一个小弹窗），不是可视化目录树选择器。云盘那侧是目录选择器；
  工作区侧每个目录都要发一次 `list` 操作，逐层点选的交互在链路上要反复排队，第一期先用输入（并给提示）。
- **批量下载没做**（与 FM-2 同一取舍）；工作区批量操作只给了"移动/删除"。
- **没有字节级传输进度**：上传进度只到"写入传输会话（60%）→ 操作完成（100%）"两档，
  真正的字节进度要等 FM-6 的分块上传。
- **未部署**：`server_release.sh` 与执行体开关（`--workspace-files`）都没动（见 FM-3 交接 §4 的部署注意）。
